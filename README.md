# QRStovykla 2027

QRStovykla consists of:

* **QRStovykla.WEB** — Next.js frontend
* **QRStovykla.API** — ASP.NET Core 10 backend
* **Netlify** — frontend hosting
* **OpenNebula Ubuntu VM** — backend hosting
* **Docker** — backend container
* **Cloudflare Tunnel** — public HTTPS access to the backend

## Architecture

```text
User
  │
  ▼
Netlify
Next.js Frontend
  │
  │ HTTPS
  ▼
api.example.lt
  │
  ▼
Cloudflare Tunnel
  │
  ▼
OpenNebula Ubuntu VM
  │
  ▼
Docker
  │
  ▼
ASP.NET Core API :8080
```

## Backend Docker Image

Navigate to the directory containing `QRStovykla.API.csproj`:

```powershell
cd QRStovykla.API\QRStovykla.API
```

Build the Docker image:

```powershell
docker build -t qrstovykla-api:latest .
```

Verify the image:

```powershell
docker images
```

## Run Backend Locally

```powershell
docker run --rm `
  -p 5000:8080 `
  -e ASPNETCORE_ENVIRONMENT=Development `
  -e Access__Password="YOUR_PASSWORD" `
  -e Access__DriveUrl="YOUR_DRIVE_URL" `
  --name qrstovykla-api `
  qrstovykla-api:latest
```

Swagger:

```text
http://localhost:5000/swagger
```

## Export Docker Image

```powershell
docker save -o qrstovykla-api.tar qrstovykla-api:latest
```

This creates:

```text
qrstovykla-api.tar
```

## Connect to OpenNebula VM

Connect to the university VPN first.

SSH:

```powershell
ssh -i $env:USERPROFILE\.ssh\id_ed25519 -p <SSH_PORT> mifsa@<PUBLIC_IP>
```

The current SSH port and public IP can be found in:

```text
OpenNebula
→ Virtual Machines
→ QRStovykla-API
→ Info
→ CONNECT_INFO1
```

## Upload Docker Image to VM

From Windows:

```powershell
scp -i $env:USERPROFILE\.ssh\id_ed25519 -P <SSH_PORT> `
  .\qrstovykla-api.tar `
  mifsa@<PUBLIC_IP>:/home/mifsa/
```

Connect to the VM:

```powershell
ssh -i $env:USERPROFILE\.ssh\id_ed25519 -p <SSH_PORT> mifsa@<PUBLIC_IP>
```

Load the Docker image:

```bash
docker load -i qrstovykla-api.tar
```

Verify:

```bash
docker images
```

## Backend Environment Variables

Create an environment file on the VM:

```bash
nano ~/.env
```

Add:

```env
Access__Password=YOUR_PASSWORD
Access__DriveUrl=YOUR_DRIVE_URL
ASPNETCORE_ENVIRONMENT=Development
```

Do **not** commit passwords, tokens, private keys, or real environment files to Git.

## Run Backend on OpenNebula

Remove the previous container if required:

```bash
docker stop qrstovykla-api
docker rm qrstovykla-api
```

Start the new container:

```bash
docker run -d \
  --name qrstovykla-api \
  --restart unless-stopped \
  --env-file ~/.env \
  -p 127.0.0.1:8080:8080 \
  qrstovykla-api:latest
```

Verify:

```bash
docker ps
```

Test the API directly on the VM:

```bash
curl http://localhost:8080/swagger/index.html
```

If Swagger HTML is returned, the API is running correctly.

## Cloudflare Tunnel

The backend should not expose port `8080` directly to the internet.

Create a Cloudflare Tunnel:

```text
Cloudflare
→ Networking
→ Tunnels
→ Create Tunnel
```

Example tunnel name:

```text
qrstovykla-api
```

Install `cloudflared` on the Ubuntu VM using the command generated by Cloudflare.

Do **not** share or commit the Cloudflare Tunnel token.

Create a public hostname:

```text
api.example.lt
```

Point it to:

```text
http://localhost:8080
```

Result:

```text
https://api.example.lt
        ↓
Cloudflare Tunnel
        ↓
localhost:8080
        ↓
QRStovykla.API
```

## CORS

The API should only allow trusted frontend origins.

Example:

```csharp
builder.Services.AddCors(options =>
{
    options.AddPolicy("Frontend", policy =>
    {
        policy
            .WithOrigins(
                "http://localhost:3000",
                "https://your-project.netlify.app"
            )
            .AllowAnyHeader()
            .AllowAnyMethod();
    });
});
```

Enable the policy:

```csharp
app.UseCors("Frontend");
```

## Security

Never commit:

```text
.env
private SSH keys
Cloudflare Tunnel tokens
production passwords
API secrets
```

SSH access to the OpenNebula VM should remain accessible only through the university VPN.

The ASP.NET API should be exposed publicly through Cloudflare Tunnel rather than by opening the Docker port directly to the internet.
